## ④ 该 reason 由哪个 RPC 方法 / 探针函数失败导致

**直接产生点（探针函数）**，均在 `scripts/lp_pool_resolve_and_rank_v1_readonly.py`：

1. `_resolve_pool_at_factory`（:346）——对每个 Slipstream 工厂发 **`eth_call`**（`getPool(tokenA,tokenB,tickSpacing)`，经 `_eth_call_hex` :304 → `rpc_with_retry("eth_call", ...)` :306–309）。异常在 :467–472 记入 `probe_errors`。
2. `_validate_aerodrome_candidate`（:378）——对候选池发 **`eth_getCode`**（:381）+ **`eth_call`**（token0 :384、token1 :385、tickSpacing :400、decimals :411）。异常在 :495–500 记入 `probe_errors`（前缀 `candidate_validation:`）。
3. `resolve_pool_with_provenance`（:432）汇总：`probe_errors` 非空 → :506–511 raise `PoolResolutionIncompleteError` → `process_candidate` :984–992 落 `permanent_fail_closed_reason="factory_registry_probe_incomplete"`、`resolve_status="UNKNOWN"`、`status="FAIL_CLOSED"`。

注意：uniswap-v3 走单工厂路径 `resolve_pool_address`（:536）/`_resolve_pool_once`（:322），**不产生**此 reason（其异常落入通用 `except Exception` → `status="ERROR"`，与 ③ 中 6 个 uniswap 池的表现一致）。

**根因（DB 中实际观测到的异常）**：`factory_probe_errors` 里全是 `OverflowError: int too large to convert to float`，它不是 RPC 层抛的，而是 RPC 连接池的退避计算溢出：

- `scripts/lp_rpc_pool_v1_readonly.py:277` `RpcPool._penalize`，**关键行 :280**：
  ```python
  backoff = self._cooldown_base * (2 ** (fails - 1))
  ```
  `_cooldown_base` 是 float（默认 2.0，:234），`2 ** (fails - 1)` 是 int。当某端点连续失败计数 `fails ≥ 1025` 时，`2**1024 ≈ 1.798e308` 超出 double 上限（1.7976931348623157e308），float×int 触发 `OverflowError`（已用 Python 验证：fails=1024 得 `inf` 不报错，fails=1025 起 OverflowError）。`_fails` 只在成功时经 `_reset`（:283）清零，所以一个长期失败的端点会单调累积到溢出。
- 传播路径：`RpcPool.call`（:343）中，try 块内 :368 的 `_penalize` 若溢出会被 :370 `except` 捕获，但 except 块内 :371 的第二次 `_penalize` 在 try 之外，溢出直接**穿透 `call()`** 抛给调用方。
- scanner daemon 在 `scripts/lp_scanner_daemon_v1_readonly.py:726` 把 `pool.call` 注入为 `_rpc_with_retry`（:781 同），因此上述两个探针函数的每次 `eth_call`/`eth_getCode` 都经过该池；一旦池内端点进入溢出态，探针即抛 `OverflowError` → 记入 `probe_errors` → 触发本 reason。

即：**reason 由 `eth_call`（工厂 `getPool` 探针）与 `eth_getCode`/`eth_call`（候选校验）探针失败导致，探针函数为 `_resolve_pool_at_factory`(:346) 与 `_validate_aerodrome_candidate`(:378)；而当前 DB 中这批失败的底层异常是 `RpcPool._penalize`（`lp_rpc_pool_v1_readonly.py:280`）指数退避的 float 溢出，并非链上 RPC 本身返回错误。**（按纪律，不对其经济含义下结论。）
