# 资金政策冲突（D02 / T25）决策材料

**这是一份给用户拍板用的材料，不是建议动用资金。** 本文只做两件事：把冲突的算术讲清楚，
把「旧的 50U 最小仓位到底是不是经济上必需」用实盘数据算出来。**未签名、未广播、未动资金，
`LIVE_READINESS` 保持 `NOT_AUTHORIZED`。**

## 1. 冲突是什么

| 政策 | 条款 |
|---|---|
| 旧（100U 单账户） | 总资金 100U，**单仓 50–60U**，reserve 40U，日亏上限 5U，总回撤上限 10U |
| 新（三桶 50/30/20） | CORE 50%、STOCK 30%、MEME 20%；活跃上限 85/70/40% |

新政策下 CORE 的**最大在仓金额**＝ `100 × 50% × 85% = 42.5U`。
**42.5U < 旧政策规定的单仓下限 50U** ——两者无法同时满足。三桶合计最大部署
`42.5 + 21 + 8 = 71.5U`。

PRD 对此的处理是 `CAPITAL_POLICY_CONFLICT`：**不自动取较宽的那个条件，
不自动改金额，LIVE 一律拒绝**，等待明确审批。这个 fail-closed 设计是对的。

## 2. 实测：50U 下限在本池**不是经济上必需的**

CORE 种子池 `0x52e6…71ca`（WETH/USDG，fee 1bp），2026-09-08 15:1x UTC 实测：

| 量 | 实测值 |
|---|---|
| TVL | $32,037,565 |
| 池价 | 2,484.57 USDG/WETH |
| 实现日波动（Stage A 2,146 样本 / 15s） | 2.038 % |
| 费收 APR（全区间上界） | 27.34 % |

持有 30 天，滑点与 gas 全计入：

| 仓位 | 费收 EV | 固定成本 | 成本占仓位 | NetCover | Shadow≥1.0 | TinyLive≥1.5 |
|---:|---:|---:|---:|---:|:--:|:--:|
| $5 | $0.1124 | $0.0210 | 0.42% | 3.235 | PASS | PASS |
| $20 | $0.4494 | $0.0240 | 0.12% | 5.694 | PASS | PASS |
| **$42.5** | **$0.9550** | **$0.0285** | **0.07%** | **6.576** | PASS | PASS |
| $50 | $1.1236 | $0.0300 | 0.06% | 6.715 | PASS | PASS |
| $100 | $2.2471 | $0.0400 | 0.04% | 7.141 | PASS | PASS |

**结论：在这个池上，$42.5 的仓位 NetCover 6.58，远超 TinyLive 门槛 1.5。
固定成本只占仓位 0.07%。旧的 50U 下限在此没有经济依据可言——
它是政策产物，不是成本摊薄的要求。** 池深 $32M、费率仅 1bp，固定成本被压得极低。

（对照：`POSITION_TVL_SHARE=0.0005` 在 $32M TVL 上允许到 $16,000，本量级完全不构成约束。）

## 3. 但这个结论建立在一个**尚未打折的费收数字**上

27.34% 是**全区间上界**，且**未经有机交易量核验**。两项折扣都只会让它变小：

- `in_range_fraction`：集中流动性头寸只在价格落在区间内时才计费（RH-04e 模块已就位，
  **实测值尚未产出**）。
- `organic_fraction`：成交量里对敲与单点集中的部分不可外推（RH-05f 模块已就位，
  **数据源 RH-05g 仍在开发**）。

把两者的乘积记为折扣系数 `k`，实测临界值：

| 场景 | TinyLive(≥1.5) 的临界 `k` | 对应有效 APR |
|---|---:|---:|
| $42.5 持有 30 天 | **0.228** | 6.24 % |
| $42.5 持有 7 天 | **0.375** | 10.26 % |

**换句话说：只要「在区间时长比例 × 有机成交量比例」高于 22.8%，$42.5 仓位在 30 天持有下
仍然达标。低于 22.8% 就不达标。** 这两个数现在都是未知量，`k` 因此也是未知量。
**在 `k` 实测出来之前，第 2 节的结论只能读作「上界下成立」，不能读作「成立」。**

## 4. 摆在用户面前的选项（我不替你选）

| 选项 | 做法 | 代价 / 含义 |
|---|---|---|
| **A. 批准把单仓下限降到 42.5U 以下** | 明确批复新的最小仓位（例如 40U 或更低），旧 50U 条款作废 | 与第 2 节实测一致；但需接受 `k` 未知的风险，或等 `k` 实测后再批 |
| **B. 提高总资金** | 总资金 ≥ 118U 时 CORE 的 42.5% 份额才 ≥ 50U | 需要追加真金白银，且不解决 `k` 未知的问题 |
| **C. LIVE 只跑 CORE，暂不三桶** | 沿用旧 100U 单账户政策，三桶只留在 Shadow | 放弃 STOCK/MEME 的分散；但改动最小 |
| **D. 维持现状** | 继续 `CAPITAL_POLICY_CONFLICT`，只跑 Shadow | 零风险；LIVE 无限期推迟 |

**我的判断（仅供参考，不是代你决定）**：现在拍板为时过早。真正该等的不是这个政策，
而是 `k` 的实测值——它一个数就能把结论从 6.58 推到 1.5 以下。建议等
in-range 折算与有机成交量两项落地后再回到这张表。

## 5. 无论选哪个，以下门槛都**仍未满足**，LIVE 都开不了

- Stage A 正向观测 **9.7 h / 72 h**，覆盖率仍需追回 99%。
- Stage B（≥14 天 Shadow，须覆盖一个周末）**未启动**。
- Stage C（≥30 天 Tiny Live）**未启动**。
- `k` 未实测（见第 3 节）。
- RH-07 的签名与广播部分**须用户单独授权**，本项目至今**未触碰**。

本文档解除的只是「不知道该怎么决定」这个状态，**不解除任何一道闸**。

# 重大更正（2026-09-08 23:5x UTC）：本文第 2 节的结论**作废**

## 起因：审计查出 gas 从未被实测

T34 的取证（`AUDIT_EVIDENCE_T21_T40.json`）指出：
`gas_usd` 只是 `gas_usd_estimate` 的直通透传，**没有任何代码校验它是否合理，
也没有 L1 data 费用项**。

于是我去核对自己填的那个值——`gas_usd_estimate = 0.02` 是我今天下午
**手填的，没有任何测量依据**。实测：

| 量 | 实测值 |
|---|---|
| RH 链 gasPrice（中位） | 0.232 gwei |
| Uniswap V3 开仓 ≈45 万 gas | $0.2595 |
| V3 平仓 ≈35 万 gas | $0.2019 |
| **开仓+平仓合计** | **$0.4614** |
| 我用的值 | $0.02 |
| **低估倍数** | **约 23 倍** |

（gas 消耗量取自该区块 8 笔真实交易的 receipt，中位 gasUsed 362,301。）

## 后果：结论翻转

用**实测 gas** 加**实测折扣** `k = in_range 0.813 × organic 0.9026 = 0.7338`
（有效费收 APR 20.06%），持有 30 天：

| 仓位 | 原结论（gas=0.02，费收取上界） | **实测 gas + 实测 k** | TinyLive ≥1.5 |
|---:|---:|---:|---|
| **$42.5**（CORE 在 100U 下的上限） | 6.576 | **1.195** | **FAIL** |
| **$50**（旧政策下限） | 6.715 | **1.354** | **FAIL** |
| $100 | 7.141 | 2.181 | PASS |
| $500 | 7.520 | 4.260 | PASS |

**临界折扣 k 从 0.228 涨到 0.9214**，而实测 k 只有 0.7338——**不够**。

**最小可行仓位：$57**（30 天持有）。持有 7 天时 $42.5 的 NetCover 只有 0.329。

## 本文第 2 节说反了

原文说「旧的 50U 下限在这个池上没有经济依据，42.5U 上限不是经济上的问题」。
**恰恰相反**：在 100U 本金下，**42.5U 与 50U 两个数都不可行**，
最小可行仓位 $57 比两者都高。

## 修正后的选项

CORE 活跃上限 = 本金 × 50% × 85% = 本金 × 0.425。要让它 ≥ $57：

| 本金 | CORE 活跃上限 | ≥ $57 | D02 冲突 |
|---:|---:|---|---|
| $100 | $42.50 | 否 | 有 |
| $120 | $51.00 | 否 | 无 |
| **$134** | **$57.00** | **是（临界）** | 无 |
| $150 | $63.75 | 是 | 无 |
| $200 | $85.00 | 是 | 无 |

**原选项 B（提高总资金）从「不解决问题」变成了唯一的工程解**：
需要**至少 $134** 才能让 CORE 桶开出一个经济上可行的仓位。
原选项 A（批准降低单仓下限）**已不成立**——降下限只会让仓位更不可行。

## 这次错在哪，值得记

我下午那份分析的每一步计算都是对的，**错在一个手填的输入没有被质疑**。
`gas_usd_estimate = 0.02` 从来没有出处，却撑起了「固定成本只占仓位 0.07%」
这个结论，而真值是 1.11%。**审计的价值正在于此：它问的不是「算得对不对」，
而是「这个数从哪来」。**

同族教训已记入 `RH-05-research/` 的静默假绿清单：
**一个没有出处的常量比一个算错的公式更危险，因为它不会在任何测试里报错。**

## 仍未处置

实测的 $0.4614 是**当前 gas price 下的值**。Arbitrum 系 L2 的 gas 由 L1 data 费用
主导，会随以太坊主网拥堵剧烈波动。T34 指出的「无 L1 data 项、无重复计费检测」
仍然成立——**gas 应该按当前链上状态动态估算，而不是任何固定常量**，
包括我这次实测的这个。已写成 `docs/specs/20260909_RH-03c_dynamic_gas.md`。
