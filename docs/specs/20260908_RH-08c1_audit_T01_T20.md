## 取证纪律（每条都必须遵守）

1. **`impl_sites` 必须是真实存在的文件与行号。** 用
   `grep -n` 定位后把该行原文抄进 `snippet`。**禁止凭印象填行号。**
2. **`covering_tests` 里的每个测试都必须真跑一遍**：
   ```
   /root/lp-bot/.venv/bin/python -m pytest "tests/<文件>::<测试名>" -q -p no:cacheprovider
   ```
   把尾行原样填进 `pytest_output`。**没跑过的测试不许写进去。**
3. **`coverage` 三选一，判据是机械的**：
   - `COVERED`：existing 测试**直接断言了 `expected` 描述的行为**。
   - `PARTIAL`：有实现代码，但测试只覆盖了一部分，或只覆盖了正常路径没覆盖 `expected` 里的拒绝路径。
   - `NOT_COVERED`：找不到实现，或找不到断言该行为的测试。
   **找不到就写 `NOT_COVERED`，这是有价值的结论，不是失败。
   编造一个勉强沾边的测试来凑 COVERED 才是失败。**
4. `notes` 只陈述事实。**不许出现「应该」「基本满足」「大体符合」这类词。**
5. 一条用例可能横跨多个模块，`impl_sites` 与 `covering_tests` 都是数组，如实列全。
