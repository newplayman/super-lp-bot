# RH-04c：markout 与逆向选择诊断（离线可测）

## 背景
PRD §12.3，用例 **T42**（同一笔 markout 在 30s/5m/30m 分列，**不得三次累加同一亏损**）。PRD 定义：
```
markout(delta)   = Δbase * ReferenceBaseUSD(t+delta) + Δquote * ReferenceQuoteUSD(t+delta)
AS_signed(delta) = -markout(delta)
```
明确规定：这只是**指定未来时点的成交标记**，不是完整 LVR 的无偏估计；使用**预注册**的观察窗口；**保留正负值**，不得把有利成交清零后只累加不利成交再声称是实际亏损；个体 LP 的 Δ数量应来自其在成交段的**实际应占份额**，不得用全池成交当本钱包损失；没有未来可信参考价时输出**未完成样本**，不用陈旧价格补齐。

## 只新建两个文件
1. `scripts/lp_rh_markout_v1_readonly.py`（≤250 行）
   - `PREREGISTERED_WINDOWS = (30, 300, 1800)`（秒），模块级常量；**函数不接受任意窗口**，传入未注册窗口抛 `ValueError("WINDOW_NOT_PREREGISTERED")`。
   - `markout(*, delta_base, delta_quote, ref_base_usd_future, ref_quote_usd_future) -> Decimal|None`：任一未来参考价为 `None` → 返回 `None`（**未完成样本**，不得用当前价替代）。
   - `as_signed(markout_value) -> Decimal|None`：`None` 透传。
   - `markout_profile(fill, *, price_lookup) -> dict`：对三个预注册窗口各算一次，返回 `{"30": …, "300": …, "1800": …, "incomplete_windows": [...]}`。**三个值分列存储，不提供求和接口**。
   - `lp_share_of_fill(*, pool_amount, lp_liquidity, active_liquidity) -> Decimal`：本 LP 应占份额 = `pool_amount * lp_liquidity / active_liquidity`；`active_liquidity <= 0` 抛 `ValueError`。**调用方必须先用它折算，再算 markout。**
   - `aggregate(profiles, *, window) -> dict`：按单一窗口聚合，返回 `{"n", "sum", "mean", "positive_count", "negative_count", "incomplete_count"}`。**保留正负两侧计数**；文档字符串写明不得跨窗口相加。
   - `main()`：`--fills-json --out`，不联网。
2. `tests/test_lp_rh_markout_v1_readonly.py`（≤250 行，≥14 测试）
   - **T42 核心**：同一笔成交在三窗口得到三个值，断言模块**没有**把它们相加的接口（`hasattr` 断言无 `total_markout`/`sum_all_windows`），且 `aggregate` 传入 `window=30` 与 `window=300` 得到不同结果。
   - 未注册窗口（如 60）→ `WINDOW_NOT_PREREGISTERED`。
   - 未来参考价为 `None` → `markout` 返回 `None` 且进 `incomplete_windows`；`aggregate` 的 `incomplete_count` 正确。
   - 有利成交（markout 为正）**不被清零**：构造正负混合样本，断言 `positive_count > 0` 且 `sum` 反映净额而非只累加负值。
   - `lp_share_of_fill`：全池成交 100、本 LP 占 10% → 得 10；`active_liquidity=0` 抛错。
   - `as_signed` 符号正确：markout 为正 → AS 为负。
