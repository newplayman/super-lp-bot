GOAL:
修 `scripts/lp_rh_reconciliation_v1.py` 的 C3 检查:它把**原始 token 单位**和**美元**直接相减。

## 现象(已实测,直接用)

## 真因(已验算,账本没问题,是检查错了)

`rh_journal.amount_raw` 存的是**原始 token 单位**;
`rh_position_marks.accrued_fee` 存的是**美元**。C3 直接相减。

runner 记账时的换算(`scripts/lp_rh_shadow_runner_v1_readonly.py`,搜 `fee_amount_raw`):

```python
fee_amount_raw = (accrued / fee_quote) * (Decimal(10) ** fee_dec1)
```

所以反向换算是 `usd = amount_raw * quote / 10**dec1`。主脑已验算:

```
dec1=6   quote=0.999963
journal raw → USD = 0.1056746313411120502635856446544932
marks accrued_fee = 0.1056746313411120502635856447
差额 = -4.55068E-29     ← 完全配平
```

**账本是对的,C3 是错的。**

## 要做的事

只改 `scripts/lp_rh_reconciliation_v1.py` 与 `tests/test_lp_rh_reconciliation_v1_readonly.py`。

1. C3 比对前,把 journal 的 `amount_raw` 按 `usd = amount_raw * quote / 10**dec1` 换算成美元,
   再与 `marks_fee_total` 比。全程 `Decimal`,**不要用 float**。

2. **`quote` 和 `dec1` 从哪来,是本包的关键。** 它们在 `reports/lp_rh/pool_meta.json` 里
   (`dec1`、`quote_usd_per_token1.value`)。但对账脚本现在**只接受 `--db`**。
   加一个 `--pool-meta`(默认 `reports/lp_rh/pool_meta.json`)。

3. **fail-close(比修复本身更重要)**:拿不到 `dec1`、拿不到 `quote`、quote 已过 TTL、
   或值不是正数时 → C3 判为 **`INSUFFICIENT_EVIDENCE`**,理由写明缺什么。
   **绝不能假设 dec1=6、绝不能假设 quote=1.0、绝不能跳过换算直接比。**
   把「换算参数拿不到」当成「可以按 1:1 比」,会把一个 10⁶ 倍的单位错误伪装成账差,
   或者反过来把真账差藏起来。
   注意 quote 的 TTL 判定:`observed_at + ttl_secs`,与 runner 的 `validate_quote_evidence` 同口径
   (**只读它的逻辑,不要修改那个函数**)。

4. 允许的容差:换算涉及 Decimal 除法,给一个**极小**的绝对容差
   (建议 `Decimal("1e-18")`),超过就算差异。**不要给一个宽到能掩盖真账差的容差。**
   在 `evidence_json` 里记下用到的 `quote`、`dec1` 和容差值,便于审计。
